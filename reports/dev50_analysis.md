# 50 题基线分析（汇总于 2026-10-16）

实验在 2026-10-15 执行。数据为固定的 MuSiQue 50 题、227 文档缩减语料开发集。统计结果见 dev50_results.md / dev50_results.json，数据完整性见 dev50_data_check.json。

## 主要结论

当前已完成模型替换后的 L2 开发集功能对照，未复现论文表格，也未证明 Idea 1 有效。官方源码未修改，但成功的 HippoRAG 运行使用了明确记录的抽取接口适配，不能称作原始提示词配置原样跑通。

| 指标 | HippoRAG（适配配置） | Dense（相同生成参数） |
|---|---:|---:|
| 平均支持文档 Recall@1 | 31.17% | 37.50% |
| Recall@5 | 81.17% | 80.00% |
| Recall@10 | 90.00% | 86.50% |
| 回答 EM | 6.00% | 6.00% |
| 回答 F1 | 14.08% | 17.36% |
| 平均每题检索与回答耗时 | 2.50 秒 | 1.01 秒 |
| 前五篇找齐全部支持文档的题数 | 28/50 | 24/50 |
| 找齐支持文档但回答 F1=0 | 15/28 | 10/24 |

Recall 是每题支持文档召回比例的宏平均，并非“第一篇命中任意支持文档的题目比例”。每题指标来自官方评估器，汇总存在单题四位小数舍入误差。

HippoRAG−Dense 的 F1 差为 −3.29 个百分点，5000 次配对 bootstrap 的 95% 百分位区间约为 [−10.72, +4.25] 个百分点。这个区间跨零；加之语料缩减、样本少和配置在开发集上调整，不能据此宣布算法优劣。

## 执行稳定性

1. 原始 Qwen 1.5B 配置在 NER 阶段失败：227 篇中 2 篇解析失败，22 条响应达到长度上限。没有产生该配置的有效检索或 QA 分数。记录为 `runs/musique-hipporag-f6af1462dc91/result.json`。
2. 单独测试重复惩罚仍无法处理所有嵌套列表；严格 JSON 提示和一次重试也不能完全解决。初版适配批次在 1 篇截断嵌套列表上失败，记录为 `runs/musique-hipporag-2d9569a5f35b/result.json`。
3. 最终 strict-json-v3 先调用官方已有的截断 JSON 修复，再规范化嵌套字符串列表/裸三元组列表。没有跳过文档或人工填入实体、三元组或答案。2 次格式重试、116 次列表结构规范化均留有记录。
4. 成功运行的 227 篇文档均有实体和三元组输出；文档级共有 1149 条三元组，图内去重后为 1135 条，图含 1530 节点、2789 条边。无空抽取不代表事实全部正确。
5. 42/50 题有图种子，8/50 题无图种子、走官方 dense 回退路径。原始响应、抽取 JSON、图和逐题答案均已保存。

## 失败分析

- 原 sample 的输入根本没有明确提供 Alzheimer’s 研究关系，不能用其单题得分评价证据推理，详见 sample_audit.md。
- 开发集上仍有证据召回不足：HippoRAG 22/50 题未在前五篇找齐全部支持文档；Dense 为 26/50。它们的 QA 都只读前五篇。
- 证据齐全仍答错：HippoRAG 的 28 个证据齐全问题中 15 个 F1=0，表明排序、上下文使用、回答生成等环节仍需诊断，不能只改图检索。
- 19/50 个 HippoRAG 答案、20/50 个 Dense 答案超过 20 个英文词。参考答案往往很短，冗长回答可能拉低 F1；不过这不能解释所有错误，不能把低分都归结为格式。
- 示例：HippoRAG 在一个参考答案为“12”的剧集数量问题上已召回全部支持文档，却回答无法确定并混淆剧集信息。另一个位置问题参考为 Atlantic Ocean，却回答 Cabo Verde。这些是实质性回答问题。

## 用量与耗时边界

所有模型调用都在本机，无外部模型 API 费用。成功 HippoRAG 运行的缓存库存为 501648 tokens，其中相对导入缓存新增 413662 tokens；Dense 为 76604 tokens。库存包含继承的响应，不能当作本次新生成量，也不等于整个调试过程的累计用量或 DeepSeek 预计账单。

HippoRAG 建索引约 415.73 秒，但复用了前次 NER 的原始响应；这不是全流程冷启动耗时。Dense 建索引约 4.74 秒。每题耗时也受服务 KV 缓存和系统负载影响，当前不是严格性能基准测试。
